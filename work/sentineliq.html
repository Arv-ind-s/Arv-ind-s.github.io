The problem

A maintenance prediction has to lead to a decision. What is likely to fail? What evidence supports the diagnosis? Who can authorize the action?

SentinelIQ connects those steps in a simulated 15-machine plant, using replayable telemetry and a mock ERP integration.

The build

Sensor streams are cleaned and transformed into 41 versioned features. scikit-learn models predict failure probability, fault mode, and remaining useful life. Deterministic fusion combines the signals into a risk assessment.

Sensor and maintenance-log agents collect evidence. A coordinator assembles a diagnosis, guardrails check the response, and an approval boundary controls the ERP action.

The decision

The model narrates; it does not own the numbers. Numerical predictions, guardrails, approvals, and ERP authorization remain deterministic.

Gemini can improve the explanation, but the system falls back to a deterministic template when there is no API key, the network is unavailable, or the circuit breaker opens. The demo can run offline.

The boundary

A planner must approve an immutable work-order payload before an A0 action writes to the mock ERP. A1 routing requires technician acknowledgement and does not write to ERP.

Role-based access, idempotent work-order creation, evidence citations, and an audit hash chain make the route from signal to action inspectable.

Scope & evidence

This is a decision-support demonstrator, not a deployed plant safety controller. The telemetry is simulated, and the ERP is a mock service. The repository includes deterministic scenarios, evaluation reports, and a repeatable demo workflow.
