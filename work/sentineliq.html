HACKATHON BUILD / WINNER

SentinelIQ

Predictive maintenance with a traceable path from evidence to approval.

Read the source code ↗Inspect the evaluation report ↗
MY ROLE & SCOPE
Solo build · Simulated 15-machine plant
CORE ENGINEERING
scikit-learn · FastAPI · React · Gemini

What I built

I built the simulated plant demonstrator end to end: telemetry replay, the predictive-maintenance workflow, grounded diagnosis, and a planner-controlled boundary before writing to a mock ERP.

Sensor streams become 41 versioned features. scikit-learn models predict failure probability, fault mode, and remaining useful life, while deterministic fusion brings the signals together.

The problem

A failure prediction has to support a decision: what is likely to fail, which evidence supports the diagnosis, and who is allowed to authorize an action?

The plant is simulated so its telemetry and scenarios can be replayed, inspected, and evaluated.

A consequential decision

I kept numerical predictions outside the language model. Gemini can improve the explanation, while the numbers, guardrails, and ERP authorization remain deterministic.

The tradeoff is a deliberately bounded role for generative AI. The workflow remains usable with an offline template when there is no key, the network is unavailable, or the circuit breaker opens.

The approval boundary

A planner must approve an immutable payload before an A0 action writes to the mock ERP. A1 routing uses technician acknowledgement and does not create a work order.

Role-based access, idempotent work-order creation, evidence citations, and an audit hash chain make the action inspectable.

What this demonstrates

The project won the TCS Kochi AI Hackathon. Its code, replay scenarios, and evaluation report are available in the repository.

This is a decision-support demonstrator with simulated telemetry and a mock ERP. Its evaluation is evidence about those recorded scenarios, not a claim of performance in an operating plant.
