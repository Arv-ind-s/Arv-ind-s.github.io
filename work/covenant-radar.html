HACKATHON BUILD / NATIONAL FINALIST

Covenant Radar

An early-warning system a credit reviewer can interrogate.

Read the source code ↗Read the architecture ↗
MY ROLE & SCOPE
Solo build · Demonstration lending book
CORE ENGINEERING
Python · Guarded LLM · Evaluation harness

What I built

I built the credit-risk workspace, REST API, nightly processing pipeline, guarded LLM integration, and review workflow end to end.

The system forecasts potential covenant breaches at 30, 60, and 90 days. Ingest, covenant testing, risk scoring, ranking, case updates, and dispatch are separate nightly steps.

The problem

A borrower can deteriorate between financial statements. Behavioral and external signals may reveal that change, but an unexplained risk score is difficult for a credit reviewer to defend.

A useful warning needs its source data, threshold, calculation, evidence, and review history.

A consequential decision

I kept contractual covenant arithmetic separate from behavioral risk. The named ratio and the threshold in force remain inspectable; risk signals add a separately identified layer.

The tradeoff is more explicit state and evidence handling. In return, a reviewer can reconstruct why a warning appeared instead of accepting an opaque score.

The review boundary

A single guarded LLM call site applies input masking, provider checks, token budgets, and prompt-hash versioning. Attempts and refusals are recorded.

Eight-role access control, maker-checker approvals, a hash-chained audit trail, and an evaluation harness define who can act and which checks gate release.

What this demonstrates

The project was a TCS National Hackathon finalist. Its source and architecture are public.

The repository describes a demo book of 24 NSE-listed Indian companies, using filed results and public-data context, plus 35 authored offline evaluation examples across ten categories. It is a demonstrator rather than a deployed lending institution’s system.
